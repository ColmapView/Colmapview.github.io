At a glance

  • Local reconstruction processing and rendering run in your browser.
  • Remote files download from the source you choose. Account access is optional and requested for private access or publishing.
  • Publishing sends dataset files to your selected provider. Hugging Face datasets are public and Drive ZIPs are shared with anyone with the link by default; you can choose Private before uploading. Bucket uploads use the bucket's existing permissions.
  • Where ColmapView Hub is enabled, every upload also creates a Hub link with a public card showing its title, description and preview. OpsiClear LLC stores the card on Cloudflare until the Hub link is deleted. You can request removal using the contact details below.
  • Disconnecting removes the app's in-memory credentials. It does not remove loaded files or published copies.
  • Current versions include no analytics. Older versions kept at their versioned GitHub Pages addresses (v0.15.4 and earlier) load Google Analytics. See section 7.

1. Who this policy covers

OpsiClear LLC maintains ColmapView, an open source web viewer for COLMAP reconstructions and related media. This policy describes the ColmapView website and its configured Google Drive and Hugging Face integrations. Account features may be disabled in some deployments. Other operators' deployments and the external services you use have their own policies.

Contact us about privacy at info@opsiclear.com.

2. Local and remote files

When you select local files, the viewer reads the reconstruction, image files, masks, Gaussian splats, configuration files, or archives needed for the features you use. It parses, transforms, and renders that data in your browser. Selecting local files does not upload their contents to a ColmapView application server.

Loading a URL or manifest makes requests to the file hosts and any image or mask hosts referenced by that dataset. Requests can expose your IP address and connection information to those hosts. The dataset's source URL, paths, filenames, and file contents are used in the browser to discover and load supported data.

Camera metadata conversion and COLMAP export run in your browser. A remote camera import can also request source directory listings and referenced photographs or masks from their hosts to resolve the dataset's file paths.

If you open a viewer link that includes a dataset URL in its query string, your browser sends that full viewer URL to the website host when requesting the page. The host may therefore receive and log the dataset URL, including a Drive file ID or access-related link parameters. This is distinct from uploading dataset contents. To avoid putting a private source URL in that page request, open the viewer first and paste the source into Load URL instead of sharing or opening a URL-bearing viewer link.

Local export saves files through your browser. Sharing a viewer URL can include a dataset URL and encoded viewer settings. Treat links, filenames, and saved configurations as potentially sensitive; anyone receiving a link can read what the link itself contains.

3. Google Drive access

Public Drive ZIP and TAR archive links, including compressed TAR, can be loaded without connecting your Google account where the Drive integration is configured. For a private archive, you choose to sign in, authorize drive.file, and select the file through Google Picker. This permission applies to files you select for ColmapView or files the app creates; it is not broad access to every file in your Drive. The account must already be allowed to download the file. Pasting an arbitrary private link does not itself grant access. ColmapView retrieves the selected archive's metadata and content; the loader does not modify source files.

Google Picker runs Google's file-selection interface in your browser. ColmapView supplies its app configuration and current Google token to Picker so you can choose an archive. After selection, the app uses the chosen file ID and, when required, its resource key to download through Google's Drive API. Cancelling the picker does not start a dataset load.

Loading and publication share one local connection with the drive.file permission. Connecting never starts an upload; publication is a separate action. The current publisher uses this connection to read your Drive account's permission ID, an identifier Google uses for your account in file permissions, and keeps that ID in the tab's memory so a retry continues in the same account. It then uploads a new dataset ZIP, labels that file with a random publication marker in its app-private metadata (appProperties) so a retry can recognize its own upload, and reads the file's metadata, including its size, checksum, marker, and sharing permissions, to verify it. The marker stays with the file in your Drive. Only if you select link sharing does the publisher create a permission allowing anyone with the link to read that uploaded file. The app does not request drive.readonly or full-Drive read/write access.

Google supplies short-lived authorization tokens. ColmapView keeps them in the current tab's memory and uses them in requests to Google APIs. They are not saved to the app's persistent browser storage or included in shared viewer links. Google account passwords are entered with Google, not with ColmapView.

Google Limited Use: Use of information received from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements. We use this information for the visible viewing and publishing features you request. We do not sell it, use it for advertising or credit decisions, or use it to train generalized AI models. Transfers occur to provide features you explicitly request, including publication to another provider as described below, or where required for security or applicable law. Maintainers do not routinely receive or read your Drive file contents.

4. Hugging Face access

Public dataset links can be opened without signing in. To open a private dataset, you choose to sign in with Hugging Face. Where publishing is enabled, every Hugging Face sign-in, including one started on the dataset-loading page only to open a private dataset, requests both repository read access (read-repos) and permission to create repositories and write to the ones the app creates (contribute-repos), and the viewer does not connect unless both are granted. A viewer configured only for private viewing requests repository read access alone. Before you sign in, the Hugging Face account control and the publishing dialog state which access the viewer requests. Hugging Face returns a short-lived access token and account profile information; ColmapView uses your username to identify the connected account and the token to retrieve permitted repository metadata, listings, reconstruction files, images, masks, and other referenced assets.

Publishing uses the contribute-repos permission and the connected username to create a new dataset under your account. Where publishing is enabled, the same connection serves loading and publishing, but connecting never starts a publication; you start one explicitly in the publishing dialog. Passwords are entered with Hugging Face. Tokens and connected account state stay in the current tab's memory rather than persistent app storage.

The Hugging Face sign-in callback uses a short-lived authorization code in a URL before the browser exchanges it for a token. The callback page request can expose that URL to website hosting infrastructure. The code is distinct from the access token and is used with a verifier held in the signing-in tab.

5. Publishing and sharing data

Publication is a separate action you start after choosing a destination and reviewing its options. It transfers a representation of the current reconstruction, original referenced images, available masks and splat files, viewer settings, and any chosen preview or dataset metadata to that provider. Original images can retain embedded metadata, including EXIF, capture details, or location information. Review your source files before publishing.

The Hugging Face publisher creates a new dataset repository that is public by default. You can choose Private before uploading. The dataset includes a card containing the title, description, and any license you select; public publication requires a license. Public files and previews can be accessed or copied by others, including while uploading. Private viewer links require a Hugging Face connection with repository access and do not contain authorization tokens.

The current Google Drive publisher creates a dataset ZIP and, by default, shares it with anyone with the link after upload verification. Choose Private to keep the ZIP private. A viewer link to a private file does not grant access; recipients need provider permission and must authorize that ZIP for ColmapView through Google Picker unless it is already available to the app.

ColmapView Hub links. Where the Hub is enabled (on colmapview.opsiclear.com and colmapview.github.io), every completed upload also sends ColmapView Hub, a service OpsiClear LLC runs on Cloudflare: the viewer link; a title (the Hugging Face title, the Drive file name or the bucket folder name); for Hugging Face uploads, the description and any license you chose; a 600 × 315 JPEG preview made in your browser; a summary of the upload's contents (asset counts and format); whether the data is public; and a random delete key, which the Hub keeps only as a hash. The Hub stores them until the link is deleted. Data anyone can open without signing in gets a short, readable link; private or unconfirmed data gets an unguessable link. Anyone with a Hub link can see its card, including the title, description, preview and viewer link, even when the dataset itself needs permission. Dataset files and provider tokens are never sent to the Hub. To request removal of a Hub card, email info@opsiclear.com with the Hub link.

A dataset initially loaded from Google Drive may be uploaded to Hugging Face if you explicitly publish it there. Similarly, files read from Hugging Face or another source may be included in a Drive publication you request. Dataset files go directly from your browser to the selected provider and are subject to that provider's terms and privacy policy. ColmapView does not automatically publish a loaded dataset.

Cancellation or failure may leave a created repository, committed files, a partial upload, or a completed private Drive file on the provider. Closing a publish dialog does not cancel the job. Provider-side copies must be reviewed and removed through that provider; deleting a viewer link or disconnecting an account does not delete them. Other people's downloads cannot be recalled.

6. Browser storage and retention

Loaded datasets, archives, decoded images, thumbnails, and publication progress are kept as working data and caches in the current browser session. The viewer does not create a persistent IndexedDB database for dataset contents. Browsers and remote hosts may still cache downloaded responses according to their own behavior.

Large archive downloads, decompressed gzip TAR contents, and photo-package exports can use temporary browser-managed disk storage on your device. The viewer removes downloaded and decompressed archive files when the archive closes. Completed export packages remain for at least 24 hours so a browser download can finish; later archive processing removes expired exports where browser lock support permits safe cleanup. Failed or cancelled exports are removed, and files left by a reload or crash are cleaned during later archive processing. Clearing this site's browser data also removes these files. This storage does not send dataset contents to a ColmapView server.

Where supported, Save ZIP to file asks you to choose a file on your device and writes the export directly there, without a browser-managed copy. The writer replaces an existing file only after the complete package validates and its final save succeeds. Cancelling or failing before that final save preserves an existing file; a newly chosen filename can remain empty. Clearing site data does not remove files saved this way.

The app saves viewer preferences, theme, named configuration profiles, and last-seen version information in local storage so they can survive reloads. A session-storage record of an unfinished automatic URL load may contain the dataset URL; it is normally removed when the attempt finishes and can remain after a tab crash to prevent repeated failing loads. Browser history and bookmarks may also retain viewer or dataset URLs.

Disconnecting or token expiry removes the app's access token for that session. Reloading or closing the tab ends in-memory account sessions and working data, although reopening a dataset link can load that dataset again. Disconnect does not erase downloaded data already displayed, saved preferences, exports, or provider-side publications.

Data uploaded to Google Drive or Hugging Face stays with that provider under its retention rules until you remove it there. If you contact OpsiClear LLC, we receive the contact details and information you voluntarily send and use them to respond and handle the request. Please send only the information needed; ask us by email to remove information you have supplied.

7. Website hosting and external services

ColmapView is hosted on GitHub Pages and Cloudflare Pages. These hosting and infrastructure services process connection information such as IP address, request time, browser information, and requested website resources to deliver and protect the website. Their handling is described in the GitHub privacy statement and Cloudflare privacy policy.

ColmapView Hub runs on Cloudflare Workers and stores Hub links in Cloudflare R2. Cloudflare keeps a sample of request logs, including connection information. To slow the guessing of Hub links, the Hub counts missing links per network using a keyed hash of your IP address (for IPv6, of its /64 network) rather than the address itself, and deletes that state at most an hour after your last missing link or link creation.

Current ColmapView versions do not include analytics scripts or create analytics cookies; see older versions below. These policy pages load no third-party scripts or fonts. Opening an account control, signing in, loading a remote dataset, following an external link, or publishing contacts the relevant external services. Those services may use their own cookies and process account or connection information under their policies. See Google's privacy policy and Hugging Face's privacy policy.

Older versions on GitHub Pages: most released versions remain available at their own addresses on colmapview.github.io, such as /v0.15.4/, so existing links keep working. ColmapView v0.15.4 and earlier versions load Google Analytics (Google tag G-7K5H83SEMY) when the viewer opens. In those versions your browser sends page-view and interaction information to Google, including the full page address with any dataset URL in its query string, the referring page, browser and device details, and connection information such as your IP address. The tag also sets Google Analytics cookies (_ga and _ga_7K5H83SEMY) for colmapview.github.io. Google handles this information as described in How Google uses information from sites or apps that use its services. ColmapView's maintainers can see the resulting Google Analytics reports, which can include those page addresses. To avoid this collection, use the current release at colmapview.github.io/latest/ or block analytics in your browser.

The website restricts outgoing referrers to the site's origin so query strings and dataset paths are not sent as referrers. Requests to the dataset provider necessarily include the resource you ask it to retrieve. Tokens are limited to the relevant provider requests, and production Google and Hugging Face API connections use HTTPS. Your device, browser extensions, source hosts, and copies you share also affect the privacy of your data.

8. Your controls and removal options

  • End app access: use Disconnect in the account control or Sign out in the publishing dialog. Each provider's connection serves both viewing and publishing. Reload or close the viewer to end its in-memory sessions.
  • Revoke provider authorization: remove ColmapView in Google Account connections or Hugging Face connected applications. This is separate from the app's local Disconnect control.
  • Clear this browser: use Reset settings on the dataset-loading page to remove saved viewer preferences, or clear this site's data in your browser to remove local and session storage, cookies, and cached responses. To remove the Google Analytics cookies that older versions set, clear the site data for colmapview.github.io. Clear browser history, bookmarks, and downloaded exports separately if needed.
  • Remove published copies: change sharing or delete the uploaded file in Google Drive; use your Hugging Face repository's settings to change access or delete the repository. Check for files or repositories left by interrupted publication.
  • Delete a Hub link: email info@opsiclear.com with the Hub link to request removal. If you saved a private delete link from an earlier upload, open it and choose Delete permanently. The dataset stays where it is; social networks may keep previews they already fetched.
  • Ask for help: email info@opsiclear.com with a privacy or deletion request. We can help with information you sent to us; we do not have a central copy of your locally processed dataset and cannot erase other users' downloads or provider-managed backups.
