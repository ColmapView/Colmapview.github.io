## Suggested recording sequence

Allow approximately 6–10 minutes, with clear narration and no skipped consent screens.

| Scene | Actions to record | Suggested narration |
| --- | --- | --- |
| 1. Identify the app | Show the deployed About page, viewer, privacy link, and support contact. In the viewer, click the version badge to open Help → About and show the policy links; touch users use Help → About. Identify the client being demonstrated. Its actual ID must also be legible in the Google consent popup's address bar in the grant scenes below. | “This is ColmapView, maintained by OpsiClear LLC. It helps users inspect COLMAP reconstructions in their browser. The privacy policy explains Google's data access and optional publishing.” |
| 2. Show the private source | In Drive, show only the disposable ZIP and its Restricted sharing setting. | “This existing private ZIP was uploaded outside ColmapView. I will authorize this specific file using Google's file picker. It is synthetic demonstration material.” |
| 3. Per-file consent | In Load Dataset, open the Google Drive account icon beside Upload configuration. Click Sign in with Google. Show account selection, the complete English consent screen requesting files used with this app, and any genuine testing warning. Pause with the app name and client ID visible in the real popup. Let the operator approve. | “Private archive loading requests drive.file. ZIP and TAR use this same permission for files selected for ColmapView or created by it. The app does not request broad read-only access to the account's Drive.” |
| 4. Pick, read, and inspect | Click Choose archive from Drive, show the real Google Picker, select the disposable private ZIP, and load it. Orbit the scene and inspect a camera/image. To demonstrate TAR too, repeat with a synthetic TAR or compressed TAR fixture containing the same authorized data. Separately reopen Picker and cancel to show the current scene stays intact. | “Selecting this archive authorizes it for the app. Google sends its metadata and bytes directly to this browser. The viewer parses and displays cameras, points, and images. Cancelling Picker starts no load. A private pasted URL alone does not grant this authorization.” |
| 5. Publication consent | Open Publish to Google Drive from the toolbar. Click its Sign in control. Show the separate local sign-in and any actual grant Google presents, with the app name and client ID visible. Google may recognize an already granted drive.file permission; do not fabricate a second grant. Approve as the demonstration operator. | “Publishing also uses drive.file, with a separate local session. It creates and manages the ZIP produced by this app; it does not request write access to unrelated files.” |
| 6. Private output | Leave Anyone with the link can view unchecked. Name the output `colmapview-oauth-review-private.zip`. Click Save private dataset, show packing/upload/verification and the receipt, then open the real Drive output and its Restricted sharing setting. | “Saving is an explicit action. The new ZIP is private by default and includes the current reconstruction, original images, available masks, active splat if present, and viewer settings. Its viewer URL does not grant others permission.” |
| 7. Explicit shared output | Start another publication with a distinct name and select Anyone with the link can view. Click Publish shared dataset, show receipt and actual Drive permissions, then open the resulting viewer link while signed out. | “Here I explicitly chose link sharing. It is enabled after upload verification. This synthetic output can be opened anonymously with the public Drive configuration.” |
| 8. Provider transfer, if available | In the same submitted build, open Publish to Hugging Face. Show its public-dataset/content warning, separate HF authorization, dataset details and explicit Publish public dataset action. Publish only this synthetic Drive-loaded scene. Show the real HF repository and receipt. | “This separate action transfers the selected dataset from this browser to Hugging Face and creates a public repository. A private Drive source is not automatically made public, but the user-selected copy becomes public here. This capability is included in the disclosed dataflow.” |
| 9. Disconnect and boundaries | Sign out of the publisher and disconnect the Drive loading account. Show that a loaded scene can remain visible, then reload and show private access requires a new local connection. Select a different pre-existing private ZIP through Picker to demonstrate that an arbitrary pasted URL does not authorize it. | “These controls forget local access tokens. They do not revoke the Google account grant or delete already uploaded files. Closing or reloading the tab clears the viewer's in-memory sessions and transfer state. Files already authorized for the app can remain eligible after reconnecting; a new private file needs selection.” |
| 10. Revoke and clean up | Show Google Account connections for the demo app and remove its access. In provider pages, delete the disposable outputs or restore their private visibility before deletion. | “Google account access is revoked separately here. Published files remain controlled in the user's provider account and require separate deletion or sharing changes.” |

For multiple production Google clients, rehearse scenes 3–7 through each real client/application entry point and identify the client in any requested recording. If HF publishing is disabled in the final submitted build, do not simulate scene 8; state that fact in the packet and describe the reviewed configuration accurately. A recording for a build with that capability should include the actual transfer.
