# Loading recovery and remaining dataset failures

The loader now accepts native camera-only models, recovers more photo arrangements, and explains failures that need another source or a local copy. This improves the surveyed public catalog; it does not establish that every online dataset or every image in a repository works.

The inventory is the existing 2,012-repository HF search catalog and 88-row broader public catalog. Detailed receipts, pinned revisions, hashes, per-source notes and reproduction scripts are in [the recovery audit](../.tmp/dataset-loading-improvements-2026-10-15/README.md). The [initial arrangement audit](dataset-layout-audit.md) records the preceding baseline.

## Implemented recovery

| Failure / arrangement | Loading behavior and export contract |
| --- | --- |
| Co-located `cameras.bin/txt` and `images.bin/txt`, no points file | Load poses from folders, ZIP/TAR and discovered HF trees; explicit manifests may omit `files.points3D`. Export a valid empty points file and empty image observations. No 3D geometry is fabricated. |
| A declared points file returns 404 or is corrupt | Fail with the original error. Only an absent/omitted file selects camera-only loading. |
| Both complete and camera-only models are present | Prefer a complete co-located model; otherwise use one camera/image pair. A same-source raw PLY fallback remains available. Select a scene folder/URL to identify a particular reconstruction. |
| Uppercase `.BIN` or `.TXT` | Detect the format consistently during discovery, parsing and optional rig/frame loading. |
| Registered names use `.jpeg`, `.FIT`, or no extension, but a unique corresponding PNG exists | Match the complete relative stem without discarding camera subdirectories or fractional timestamps. Competing files remain ambiguous. FITS decoding is not implemented; a supplied PNG preview can be used. |
| Registered `dslr_images/a.JPG`, physical `images/a.JPG` | Infer a collection only when registered stems are unique across the whole model and files are directly in a recognized photo directory. Preserve camera IDs, names, poses and calibration. |
| Qualified registered names such as `cam/a.jpg`, with `a.png` directly in the selected scene root beside `sparse/` | Recover the root photo collection with the same whole-model unique-stem and one-file-per-name guards. Relative, absolute and signed URL listings retain their physical resource paths. Repeated camera basenames remain unresolved; arbitrary unrecognized directories do not gain automatic flattening. |
| Model and photos live in different branches | Offer compatible collections for explicit selection. A foreign named scene must share the selected scene name; repeated frame filenames alone do not establish a match. A full physical CSV/manifest mapping can identify other intentional sharing. |
| Multiple RGB, thermal, rendered, repaired, train/test or resolution variants | Present **Choose source photos**, with folders and matched counts. The bounded candidate budget prioritizes the selected scene. The user may keep existing matches or load camera geometry without photos. Cancellation preserves the previous scene. Selecting a collection does not certify its calibration or modality. |
| Renamed original files | Honor scoped `image_mapping.csv` and manifest `imageNameToPath`, including complete physical mappings into auxiliary-looking directories. Qualified camera paths never fall back to another camera's basename. |
| A scoped mapping uses `segmentation/cam/a.png` inside a dropped `outer/scene/` folder | Resolve qualified physical suffixes even when that directory is excluded from ordinary RGB inference. Bare mapped basenames still use photo candidates; qualified relative mappings retain known scene boundaries. Only full physical/per-image mappings authorize intentional sharing. |
| Separate model / RGB / mask hosts | Explicit manifests accept absolute HTTP(S) file/mapping URLs, including existing query strings and percent escapes. Declared image/mask lists override prefix inference. Each host still needs browser-readable access. |
| Manifest lists use folders such as `segmentation/` for photos and `annotations/` for masks | Explicit `images` and `masks` lists declare their media roles and take precedence over directory-name heuristics. An image list does not replace a complete server listing or suppress a separately declared `masksPath`. Known peer-scene ownership from a complete listing still applies. Empty lists remain authoritative for unmapped images/masks; explicit per-image and per-mask mappings take precedence over those lists. |
| Absolute listed media URLs point back into the source's own tree | Compare same-origin URLs inside the exact source directory with relative layout paths for scene ownership. Keep original URL escapes and queries for fetching. Other origins and similarly prefixed directories do not inherit that relative owner. Explicit per-image sharing remains available. |
| A declared image list flattens registered camera subdirectories, including signed absolute URLs | Recover a consistent collection when registered stems are unique across the whole model. Arbitrary declared photo directories are eligible. Match decoded URL pathnames while retaining original URL escapes and queries; hosts remain distinct collections. Filename-case collisions and repeated camera basenames remain guarded. |
| A complete per-image mapping deliberately shares another scene's photos | Keep the selected camera model and infer masks from the resolved photo's owner. If that peer has no mask, do not borrow the selected scene's same-named mask. Explicit mask mappings and user-declared manifest prefixes can declare another intentional association. A media-role list or a missing photo's registered filename alone does not authorize borrowing another known scene's media. |
| Nonstandard mask directories or suffixes | Bind sidecars for display. An explicit `maskNameToPath` and `maskRole` can declare their meaning. Undeclared roles remain unknown and cannot silently become COLMAP feature masks. |
| Conventional masks are found through list/suffix recovery or signed URLs | Infer validity only from a decoded `masks/<full registered name>.png` path, consistently for preferred and fallback matches. Query parameters remain untouched. A `masks/` ancestor above a different mask root does not establish validity semantics. |
| Conventional masks use a renamed physical photo's filename | The exact `images/<physical name>` to `masks/<physical name>.png` sibling convention also establishes validity after the photo is resolved. Export rewrites the mask path to the registered name. Stem-only sidecars retain unknown semantics. |
| Signed resource URLs and relative listings describe the same image or mask path | Compare complete logical identities without query signatures, retaining the original listed physical URL for fetching. Competing signed candidates remain ambiguous. Query handling does not remove origin or known scene ownership. |
| HF discovery generates a sibling `masksPath` | Treat that generated prefix as inference when a complete physical listing exists. Bind masks to the resolved photos instead of letting the generated prefix override ownership. Explicit user-authored manifest prefixes retain their priority. |
| Absolute media URLs use a source-base directory named `images`, `masks`, or `depth` | Classify media using paths relative to the known source base. Hosting directories cannot declare image/mask roles; actual auxiliary directories inside the source remain excluded from RGB matching. |
| Signed URL query values contain image/mask/depth directory names | Exclude query text from role and collection checks. Retain the original physical URL, including its query, for fetching. |
| Mapping CSV listings and model references mix relative, absolute or signed representations | Select the nearest ancestor mapping using logical resource identities and fetch its original physical URL. Competing mappings at that nearest scope produce an ambiguity warning; other origins and similarly prefixed source directories do not acquire the selected source's relative scope. |
| Equivalent source URL prefixes use different percent-escape spellings, such as `%E7` and `%e7` | Normalize escape case and unreserved characters when comparing source-directory segments. Preserve encoded delimiters, origin, filename case and directory boundaries, and retain original fetch URLs. Equivalent encodings cannot bypass a known peer scene's photo or mask ownership. The comparison follows [RFC 3986 normalization rules](https://www.rfc-editor.org/rfc/rfc3986#section-6.2.2.2). |
| PhoMo text adds sun direction, observation intensity, normals and albedo | Read the exact declared public text schema and retain its geometric fields. Native COLMAP export omits photometric fields and warns about that omission. Unknown declared column layouts fail explicitly. |
| Native text names contain spaces, or a camera-only file ends immediately after a complete pose header | Retain the complete name and pose. Camera-only exports write complete empty observation rows, including the final row. |
| Photos are missing | Retain native camera geometry and report the matched count. Complete RGB package export requires every selected original image to exist and pass calibration checks. |
| A native mask exists but its RGB photo is missing | Keep mask reading and the separate **Download Masks** action available for folder, ZIP/TAR and URL sources. Do not fabricate an RGB binding. COLMAP geometry can still be exported separately. |
| Standard points text omits the optional track comment or uses `TRACK[]` | Accept the ordinary eight point fields and either standard track declaration. Reject unknown declared trailing fields instead of interpreting them as observation tracks. |
| Registered names are fractional timestamps without an image extension | Preserve the fractional part in photo and mask matching. A mask for `1697287.png` cannot substitute for `1697287.12345`. Only known image suffixes are removed. |
| HTTP 416 for a valid archive range | Report the rejected range and recommend a downloaded local archive or a host with working ranges. Do not silently fetch the entire object. |
| Remote index requires a fallback download larger than 512 MiB | Stop with a local-file recovery message. Small archive fallbacks remain bounded; indexed ZIP/TAR access continues to support large offsets. |
| Archive changes during reading, returns the wrong range, or denies access | Reject mixed/incomplete bytes and cancel the response body. Keep authenticated access errors intact. |
| Opaque browser fetch error | Explain connectivity, access and CORS possibilities, with a local-folder/archive route. A generic browser `TypeError` does not prove CORS. |

COLMAP geometry follows its [public model specification](https://colmap.github.io/format.html). Package export retains original image bytes and validates dimensions/orientation against calibration. Original versus downsampled views are not interchangeable for package export. A standard validity mask keeps COLMAP's [full-name `.png` convention](https://colmap.github.io/faq.html).

## Host and data failures that remain

The earlier browser audit qualified 320 of 326 exact asset URLs from both deployed viewer origins. That does not qualify all files in those sources. The six excluded URLs remain explicit exceptions: Apple Neuman and INRIA `tandt_db.zip` block CORS; three mirrors of the same 13.7 GB ZIP reject valid tail ranges; the pinned Perry metadata URL returns 404. The dated receipts distinguish browser errors from server-side range access. A local download remains subject to the host's ordinary access rules.

Some Nerfstudio Dozer mirrors contain only a subset of registered photographs. Poster frame names cannot fill those gaps. PlanarGS alignment-only branches, custom driving layouts, renamed photos without a mapping, separate/nested image archives, raw/EXR/video-only RGB and Parquet/Arrow camera shards still need source-specific assets or conversion. A declared custom schema is not accepted merely because its filename resembles COLMAP.

The October 16 inspection of [3division/Replica_Top1_Crops](https://huggingface.co/datasets/3division/Replica_Top1_Crops) finds 281 JPEG object crops and label JSON across all four complete ZIPs. No intrinsics, camera poses, 3D coordinates or crop transforms are supplied; point fields are counts. All images decode independently, and fresh browser GET/tail-range checks pass for every archive from the production origin. The published viewer rejects all four archives at scene validation; two original crops load successfully as loose gallery images. Image-only ZIP gallery support is a separate, bounded extension. Valid camera export additionally requires the matching original poses/intrinsics and source-to-crop transforms; a generic JSON parser cannot supply them. See the [source inspection and concrete support proposal](../.tmp/replica-top1-crops-investigation-2026-10-16/README.md). The broad survey's original `archive_unverified` entry was a candidate, not a passed camera-data load.

TIFF, raw and other encodings can have valid paths while remaining unsupported by the browser's image decoder; matching a filename does not verify pixels. Browser memory and the existing mask/media limits still constrain large scenes. Photo-package download streams to browser-managed disk storage and requires available disk space and browser quota; only the fallback for unavailable writable storage retains a 256 MiB output limit. **Save ZIP to file**, where the native picker is available, bypasses that staging quota and fallback limit. Both actions validate the same content and discard incomplete ZIPs before committing the chosen file or starting a download. A save cannot be cancelled once its final file commit starts. WASM-backed sparse point exports retain the existing float32 point-coordinate limitation; original camera poses/intrinsics are preserved in double precision. Dataset access and usage licenses remain separate from support for an open file format.

## Explicit manifest example

Omit `points3D` only for an intentional camera-only model. Use explicit mappings when filenames or hosts differ; the registered name remains the key.

```json
{
  "version": 1,
  "baseUrl": "https://models.example.org/pinned-scene/",
  "files": {
    "cameras": "sparse/0/cameras.bin",
    "images": "sparse/0/images.bin"
  },
  "imageNameToPath": {
    "camera_1/frame.jpg": "https://rgb.example.org/originals/frame.png"
  },
  "maskNameToPath": {
    "camera_1/frame.jpg": "https://masks.example.org/frame.png"
  },
  "maskRole": "validity"
}
```

`maskRole` accepts `validity`, `foreground`, or `unknown`. Declare it only when the mask semantics are established. All selected photographs must be available for COLMAP + images export; known masks must also pass the feature-mask validation for COLMAP + images + masks.

Directory prefixes must identify directories. Use individual absolute file mappings for signed URLs with query parameters; a query-bearing file URL cannot serve as an appendable folder prefix.
