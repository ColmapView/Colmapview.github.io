## S1-1. One module for the two dataset timeout warnings (X11(e))
**Where:** `src/hooks/optionalSettingsWarning.ts:1-18` and `src/hooks/splatListWarning.ts:1-18`. Dismiss pairs at `useUrlLoader.ts:141-142`, `useFileDropzone.ts:41-44` and `reconstructionStore.ts:721-722`. Shows at `useUrlLoader.ts:161-162`.

**Change:** replace both modules with `src/hooks/datasetTimeoutWarnings.ts`: one factory, two instances, and one `dismissDatasetTimeoutWarnings()`. Each of the three sites then makes one call. The exported message constants are unchanged.
```ts
function datasetWarning(message: string) {
  let id: string | null = null;
  const dismiss = () => { if (id) useNotificationStore.getState().removeNotification(id); id = null; };
  return { show: () => { dismiss(); id = useNotificationStore.getState().addNotification('warning', message); }, dismiss };
}
export const optionalSettingsTimeoutWarning = datasetWarning(OPTIONAL_VIEWER_SETTINGS_TIMEOUT_MESSAGE);
export const splatListTimeoutWarning = datasetWarning(SPLAT_LIST_TIMEOUT_MESSAGE);
export function dismissDatasetTimeoutWarnings(): void { optionalSettingsTimeoutWarning.dismiss(); splatListTimeoutWarning.dismiss(); }
// useUrlLoader.ts:141-142 → dismissDatasetTimeoutWarnings();   :161-162 → guard(optionalSettingsTimeoutWarning.show), guard(splatListTimeoutWarning.show)
// useFileDropzone.ts:41-44 → onSceneReplaced: dismissDatasetTimeoutWarnings,   reconstructionStore.ts:721-722 → dismissDatasetTimeoutWarnings();
```

**Why simpler:**
- One mechanism instead of two copies.
- Three dismiss pairs become three calls.
- Six imports become three.
- Production goes from about 36 + 9 lines to about 22 + 3.
- The two 33- and 35-line twin test files merge into one `describe.each` file.

**Evidence:**
- **Dismissals:** `dismissOptionalSettingsTimeoutWarning()` has 3 production calls and `dismissSplatListTimeoutWarning()` has 3. They are always paired, settings first (`useUrlLoader.ts:141-142`, `useFileDropzone.ts:42-43`, `reconstructionStore.ts:721-722`).
- **Test-only single dismissals:** `useUrlLoader.test.ts:126` and `urlLoaderManifestSource.test.ts:54`.
- **Equivalence:** every site makes the same notification-store calls in the same order, and each warning keeps its own id in its own closure.
- **No e2e or script references** to either module or message.

**Risk:** low. The change is mechanical, with no logic or ordering change.

**Tests:**
- **Merge:** `optionalSettingsWarning.test.ts` and `splatListWarning.test.ts` become `datasetTimeoutWarnings.test.ts`. The three shared cases run per warning. Keep the `SPLAT_LIST_TIMEOUT_MESSAGE` text pin, and add one case: `dismissDatasetTimeoutWarnings` removes both warnings and nothing else.
- **Import updates:** `useUrlLoader.test.ts:23-24`/`:126`, `useFileDropzone.test.ts:15-16`, `urlLoaderManifestSource.test.ts:10`/`:54`/`:285` and `reconstructionStore.test.ts:26-31`/`:2098-2099`.

- **What proves the behaviour is unchanged:**

  - `urlLoaderManifestSource.test.ts:280-296`.

**Size:** M (mechanical). **Recommend.**

## Considered, not listed
- **Optional inputs for `anySignal`:** accepting absent (null or undefined) inputs and returning a lone one unwrapped would collapse 7 `x ? anySignal([...]) : y` ternaries, all in range: `useUrlLoader.ts:171`, `fileDropzoneWorkflow.ts:303-304`, `urlLoaderViewerState.ts:29` and `:31`, `urlLoaderManifestSource.ts:120` and `:151-152`, `zipValidation.ts:45`. This preserves behaviour if operand order is kept, but it changes a shared utility's contract for a modest gain.
- **`loadZip` three-way call (`urlLoaderZipSource.ts:76-80`):** this could be one call with trailing `undefined` arguments. Two exact-arity assertions change (`urlLoaderZipSource.test.ts:55`, `:108`), for −4 lines.
- **Hub access check (`useUrlLoader.ts:261-266` and `:335-341`):** identical once S1-2 lands. A helper saves about 1 line net, and it adds a promise hop on non-Hub URLs unless it is written awkwardly.
- **The deadline races (`urlLoaderViewerState.ts:41-60` and `urlLoaderManifestSource.ts:79-101`):** they share an abort-reject scaffold. Merging them, or using `awaitWithAbort`, moves the TimeoutError abort by a microtask or adds timer re-checks. That is a timing risk.
- **Images-only commit (`fileDropzoneWorkflow.ts:503-526`) vs `replaceWithSplatOnlyScene` (`:395-403`):** they look alike, but one reports the replacement after the commit and the other before it. Merging them would reorder side effects.
- **Out of range:** `clearUrlError`/`urlError` returned by `useUrlLoader` (`:347-349`) have been unused in production since before v0.15.4.
