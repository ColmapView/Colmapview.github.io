## Considered and rejected

- **`index.css:2357-2367`.** The new 600 px tier's `.control-panel-responsive { gap: 0.125rem }` repeats the 650 px and 760 px tiers, so it is redundant in the cascade. But `toolbarColumnHeight.test.ts:74-96` requires every height-tier block to declare that gap, so removing it means changing the test parser.
- **`ABOUT_PANEL_CLASS`'s `gap-2` and `py-1`.** `.hotkey-help-about` in `hotkeyHelp.css` overrides them, but removing them changes the class attribute, which is DOM output.
- **`ModalDialogShell`'s two backdrop handlers (`:91-95` and `:110-114`).** Both halves predate the range.
- **`vite.config.ts:10-11`, `process.env.X ?? loadEnv(...).X`.** Vite 7.3.1's `loadEnv` already prefers `process.env`, but removing the short-circuit would read the `.env` files, and apply their `process.env` side effects, earlier. It saves one line.
- **`npm run check` running `typecheck:tests` before `build`'s `tsc -b`, which checks the tests again.** This is a deliberate fail-fast order.
- **`fetchDatasetResource(url, undefined, init)` at 7 call sites.** Reordering its parameters away from `fetchWithTimeout`'s would churn S1 and S3 files.
- **Turning `closeZipArchive`'s try/catch into an async function.** That changes microtask timing and how a non-promise return is handled.
- **Drive test support.** The host-gate stubs (`location` plus `VITE_GOOGLE_DRIVE_ENABLED` plus `ALLOWED_ORIGIN`) appear as 11 blocks across 7 Drive test files, 4 of them also stubbing PROD/DEV. Three hand-rolled `GoogleOAuthSdk` fakes exist: `auth.test.ts:4-9`, `DatasetAccountButtons.test.tsx:37-56` and `picker.test.ts:34-39`. A shared `src/test` helper could serve them and save about 20 lines. It is below the cut; treat it as an optional follow-up.
- **`profiles.test.mjs`.** It has 13 `yaml.load(readFileSync('.github/workflows/…'))` calls, and the two `fetchVerifiedArtifact` tests (`:405-440`) share an identical fixture and server setup. The savings are small.
- **`ExportPanel.test.tsx` and `TransformPanel.test.tsx`.** Their Reload tests are near-identical but already stub confirmation differently (a `requestConfirmation` mock versus a `window.confirm` spy). Worth knowing for whoever touches them next.
